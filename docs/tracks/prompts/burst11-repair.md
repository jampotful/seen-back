# Burst 11a: repair the closed Codex branches so their work can be merged (Sonnet, medium effort)

Start with `burst2-common.md`. Your track is `repair`; work on `agent/repair`. Stop after 150 minutes. The research desk owns `docs/views/**` evidence on its own branches and merges there; you write only `tools/views/repair_codex.py`, its test, `docs/views/repair/**` and a branch `repair/codex-17oct` that holds the repaired evidence lines. Never edit an evidence file on `main`.

Background: Codex pull requests 18, 19 and 20 (branches `codex-round-2026-10-16`, `codex/round-2026-10-17-0200`, `codex-round-2026-10-17`) were closed unmerged after audits 28, 29 and 31 (`docs/tracks/progress/audit-28.md`, `audit-29.md`, `audit-31.md`) found 50%, 84% and 94% errors; 15%, 42% and 12% without the partial-flag faults. The shared faults: compiled, table or review reads logged without `partial: true`; journal fields without volume, issue or pages; quotes cut mid-sentence with no cut marked; author lists shortened. The ledger rule: nothing is rewritten; an old line is retracted and a corrected copy appended (see `tools/views/crossref_compare.py` and how the desk's Crossref fix does it).

1. Read the three audits and the desk's `crossref_compare.py` and the partial-flag fixes file read by `gaps.py` (`docs/views/` on main; find it with grep for "partial"). Do not duplicate them: reuse their method and file formats.
2. Write `tools/views/repair_codex.py`: for the evidence lines a Codex branch adds (diff against main), (a) set `partial: true` where the note or quote shows a compiled table, review, appendix or pooled abstract, using the same rule the audit used (audit 27); (b) flag lines whose quote starts mid-sentence or ends before the sentence does, as `requote` candidates in a report (do not invent quote text); (c) list journal fields missing volume or pages for the Crossref step the desk runs. Output corrected copies and retractions in the ledger format. Everything is deterministic; no model calls. Tests with fixtures.
3. Apply it to the three branches' added lines. On `repair/codex-17oct` put the combined set of the three branches' evidence files plus the repair lines, so one pull request can bring in the work. Open nothing; the desk audits.
4. Draw a seeded sample of 20 of the repaired records (`random.seed(11)`), check each with WebFetch the way `audit-31.md` describes, and report the error rate of the repaired set, listing what is still wrong. Write it to `docs/views/repair/REPORT.md` with counts per fault.
5. Add to `docs/tracks/prompts/codex-round.md` and the item prompts (`round3-sweep.md`, `oa-pass.md`, `round4-harvest.md`, `external-sweep.md`) one short rule block that prevents the shared faults at the source: mark `partial: true` for any compiled, table, review or pooled-abstract read; copy volume, issue and pages from the page; mark every cut in a quote with an ellipsis and never begin mid-sentence; copy the full author list.

Push `agent/repair` and `repair/codex-17oct` at least every 15 minutes. Merge only the tool, its test, the report and the prompt edits to `main` after the tool's tests pass (fetch and rebase first). Final report, at most 150 words: counts, the sample's error rate, last commits.
