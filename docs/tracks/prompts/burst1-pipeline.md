# Burst 1: the extraction pipeline (Sonnet)

You build the script and the build-machine job that turn the literature collection into a table of candidate measurements, so that later agents search a table instead of reading papers. Work on the branch `agent/pipeline`; push within 10 minutes and then every 15. Stop after 75 minutes.

1. **Read** `docs/views/research/BRIEF.md` (the log format and trait keys), `tools/senses/check.py`, `tools/lit/harvest.py` and the README on the branch `pub/lit-t1` (fetch it with `--filter=blob:none --no-checkout` and a sparse checkout of one small topic, such as `spider-night`, for the dry run).
2. **Write `tools/lit/extract.py`.** It reads a topic's `index.jsonl` and `text/`, splits each full text into passages of about 1,500 words (abstracts are one passage), and sends them to Claude Haiku through the Message Batches API with a cached system prompt that gives the trait keys, the log format and three worked examples. Each result is zero or more JSON records in the log format with `taxon`, `trait`, `value`, `units`, `where` and a verbatim `quote` of at most 40 words, graded `m` or `g` by whether the measured taxon is named. A check pass greps every quote in its source text and drops any record whose quote is not found or whose record fails `check.py`. Output: `lit-table/<topic>.jsonl` plus a summary of counts and cost. Confirm the current Batch and cache prices on https://platform.claude.com/docs/en/about-claude/pricing before building, and write the per-topic cost estimate into the summary.
3. **Calibrate.** The branches `research/birds`, `research/cat-dog` and `research/ground-invertebrates` hold 593 records made by agents. For the sources those records cite that are in the collection, run the extractor and report what share of the agents' values it recovers and how many it adds. This decides how far the table can be trusted.
4. **Write `.github/workflows/lit-table.yml`** and `ci/lit/table.sh` in the pattern of `ci/lit/harvest.sh`: a push to `run/lit-table/<label>` runs the extractor over the topics named in `ci/lit/table.env`, publishes `pub/lit-table` through `ci/put_branch.sh` (no file over 95 MB), and returns the summary to the `ci` branch. The key comes from the repository secret `ANTHROPIC_API_KEY`; the job fails plainly if it is absent. Cap each run's spend with an environment variable.
5. **Dry run** one small topic from your machine if the key is available to you, otherwise end with the job ready and the calibration done on whatever the collection's full texts allow without the API (the grep and format checks).

Privacy: only the public collection goes through this job. The owner's library papers never enter the repository or this pipeline. Final report at most 250 words: the recovery share from the calibration, the cost per topic, what is ready, and your last commit.
