# Audit of the control room's OA reading pass (18 October 2026)

You are auditing evidence records you did not write. Five reading agents logged them from free copies of papers fetched by the `oa` job (`docs/tracks/prompts/oa-read.md` says how). The branch to audit is named in your launch prompt. The rules are the ones the research desk's audits enforce: read `docs/tracks/progress/audit-31.md` and `audit-39.md` for the verdicts and the counting rule, and `docs/views/research/BRIEF.md` for grades and fields. A record counts as an error when any of these is wrong: the quote (not in the paper exactly, cut with no mark, starting mid-sentence), the value (not what the quote says, or more than it says), the taxon, the grade (`m` only for one named species measured in this paper), or the partial flag (true for anything from a review, a compilation, a cited study or a figure). Metadata faults (journal, authors, pages) are written down separately and do not count, as in audit 31.

## Setup: your own key and texts
1. Clone `https://github.com/jampotful/seen-back`, check out the branch to audit. `pip install cryptography`. Make a key that never leaves your machine: `mkdir -p /tmp/oa && openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:3072 -out /tmp/oa/priv.pem && openssl pkey -in /tmp/oa/priv.pem -pubout -out /tmp/oa/pub.pem`.
2. Draw the sample first, before reading anything: all evidence lines the branch adds to `docs/views/evidence/oa-*.jsonl` (diff against `main`), then `random.seed(1018)` and `random.sample(lines, 40)` (all of them if fewer). Write the 40 ids (file:line) into your report before checking any.
3. Fetch the sampled papers' texts: from `main`, make a branch `run/oa/audit-1018` whose only change is `ci/oa/pub.pem` replaced by your `/tmp/oa/pub.pem` and `ci/oa/list.jsonl` cut to the sampled papers (match each record's DOI or title to the list's lines). Push it; the `oa` workflow returns `runs/oa/<run>-<batch>/` to the `ci` branch in 5 to 15 minutes (`git fetch --depth 1 origin ci && git show origin/ci:INDEX.txt | grep audit-1018`). Decrypt with `python3 ci/oa/decrypt.py /tmp/oa/priv.pem <dir>/enc /tmp/oa/txt`. Keep texts and the key out of the repository.

## Checking
For each sampled record: run `python3 -I tools/views/quotecheck.py /tmp/oa/txt/<batch>-<entry>.txt` on it; read the sentence or table row around the quote in the text; then give one verdict: `confirm`, `requote` (quote faulty, value right), `correct` (value, taxon, grade or partial wrong; give the right one), `retract` (nothing in the paper supports it). Write the verdicts as a table in `docs/tracks/progress/audit-oa-1018.md` with a one-line reason each, the error count and rate (requote, correct and retract count as errors), the metadata faults as uncounted rows, and the fault patterns you see. Write corrections as JSON lines in `docs/views/recheck/recheck-oa-1018.jsonl` (the recheck-5 schema: the record's id, the field, the old and new value, the reason). Do not edit any evidence file.

Commit to a branch `agent/oa-audit-1018`, push, and reply in at most 120 words: sample size, errors and rate, the main fault pattern, last commit. Stop within 90 minutes.
