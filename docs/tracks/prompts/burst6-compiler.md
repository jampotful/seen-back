# Burst 6: the spec compiler (Sonnet)

Start with `burst2-common.md`. Your track is `compiler`. Read `docs/views/COMPILER.md` (the engine track's design for it) and `docs/ENGINE-DESIGN.md` section 3, then `docs/ENGINE.md`. The table is complete on `pub/lit-table` (34 topics, one `<topic>.jsonl` each, Haiku extractions with every quote checked), the specs for the sixteen offered views and the views behind `?try=` are in `views/`, and the owner's Console workspace allows you up to $12 (about $50 of the $150 cap is spent). Stop after 120 minutes. Do not launch research units, do not touch the owner's Drive, and leave every `research/*` branch unchanged.

1. Build `tools/views/compile.py` as the document specifies: for one view, send the schema, the nearest existing spec as an example, and the records for that view (the evidence logs and the table, found by taxon and trait) to Claude through the Message Batches API (Haiku 5.5 for the drafts), and check every reply by script: the spec checker, each quote found in its source text, grades honest (`m` only where the measured taxon is the view's taxon), `invented` marked where no record gives a value, values inside the visibility floor's range (`docs/views/floor.json`). Use the audit's verdicts (`docs/views/audit/ALL.jsonl` on `main` if it exists, else `agent/audit`) to drop retracted records and use corrected values.
2. A job `.github/workflows/views-compile.yml` with `ci/views/compile.sh` and `ci/views/compile.env`, in the pattern of `lit-table`; a push to `run/views-compile/<label>` runs it and returns the drafts to the `ci` branch and to `pub/views-draft`.
3. Run it for two views whose specs exist and whose research is deep (the jumper and the bee), compare the compiler's draft with the hand-made spec parameter by parameter, and report where it agrees, where it adds and where it is wrong. Then run it for the views that have no spec yet, if any remain in `docs/COVERAGE.md`, writing drafts only to `pub/views-draft`.
4. Never merge a compiled spec into `views/` yourself; the control room decides from your comparison.

Final report, at most 250 words: the agreement with the hand-made specs, the spend, where the drafts are and your last commit.
