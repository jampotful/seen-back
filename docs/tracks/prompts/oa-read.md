# OA reading pass (control room, 18 October 2026): read the free copies the oa job fetched

Codex rounds left 300 entries of `oa-1` to `oa-10` undone, and their three last pull requests failed audit (50% to 94% errors). The control room's `oa` job (`ci/oa/oa.py`, build machines) looked every entry up and fetched 62 free copies whose text names the paper's title. You read some of them, as `docs/tracks/prompts/oa-pass.md` asks, with the full text on your own machine, so every quote can be checked mechanically. Audits 16 to 39 (`docs/tracks/progress/audit-*.md`) list the faults that sank earlier rounds; this prompt is written against them. Read `oa-pass.md`, `docs/views/research/BRIEF.md` (record fields, trait keys, grades) and audit 31 and 39 before your first record.

## Setup: your own key, your own fetch
The texts are fetched again for you, encrypted to a key that only your machine holds, so no key ever travels.
1. Clone `https://github.com/jampotful/seen-back` (depth 1 is enough). `pip install cryptography`. Make your key: `mkdir -p /tmp/oa && openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:3072 -out /tmp/oa/priv.pem && openssl pkey -in /tmp/oa/priv.pem -pubout -out /tmp/oa/pub.pem`. The private key stays in `/tmp/oa`: never commit it, print it or send it anywhere.
2. From `main`, make a branch `run/oa/read-<letter>` whose only change is: `ci/oa/pub.pem` replaced by your `/tmp/oa/pub.pem`, and `ci/oa/list.jsonl` cut down to the lines of your entries (match `batch` and `entry` against your launch prompt). Commit and push it. The `oa` workflow runs on build machines (5 to 15 minutes) and returns its results to the `ci` branch under `runs/oa/<run number>-<batch>/`, one line per batch in `INDEX.txt` naming your branch. Poll with `git fetch --depth 1 origin ci && git show origin/ci:INDEX.txt | grep read-<letter>` every two minutes until all seven batch lines are there, then `git archive origin/ci runs/oa/<run number>-<batch> | tar -x -C /tmp/oa` for each of your batches.
3. Decrypt each batch: `python3 ci/oa/decrypt.py /tmp/oa/priv.pem /tmp/oa/runs/oa/<run number>-<batch>/enc /tmp/oa/txt` (it checks each text against the checksum in that run's `lookup.jsonl`). A paper that failed this time (see that `lookup.jsonl`) is skipped and named in your report.
4. Do your reading on a branch `agent/oa-read-<letter>` made from `main` (not from the run branch).
3. `ci/oa/sources-r1.jsonl` holds, for each paper read, the `source` object to copy into every record from it: the full author list, year, title, and the journal string with volume, issue and pages, all from Crossref. Where `metadata_gaps` names something missing (often pages), take it from the paper's own first page and fill it in. Where the text itself says it is an author manuscript, accepted manuscript or preprint, say so in `note`; a PubMed Central or Europe PMC copy of a published paper is the published version whatever `copy` says.

## Reading
For fresh plant `sense_light_nonvisual` records, apply [LIGHT-RESPONSE.md](../../views/research/LIGHT-RESPONSE.md). State the evidence basis in `method`, keep observational wording in `value`, and distinguish measured comparisons from author interpretations. A common-garden provenance difference alone cannot establish a light response. Reuse the ordinary source reconciliation; this adds no second receipt or verification pass.

Read each paper whole, with its tables, figure captions and appendices, in the order your launch prompt gives. The text file holds the plain text first and, for PDFs, the same pages again after `=== LAYOUT ===` with columns kept, which is where tables are easiest to read. Log every measurement of a trait in BRIEF's list for every species in the paper, on the owner's lists or not, one record a value, with `python3 -I tools/senses/addlog.py <batch> < records.jsonl` (unit = the batch, e.g. `oa-9`).

The rules the audits enforce:
- **Length**: at most 40 whitespace-separated words, as `tools/senses/check.py` counts them, with no character limit. Do not discard a sentence merely because it exceeds 125 characters. A summariser's output cap is a retrieval constraint; use legally obtained source text, not paraphrase or pieces requested to bypass that cap. If the text cannot be obtained, record the retrieval gap. The omission, scientific-support and provenance rules below still apply.
- **Quote**: copied exactly from the plain-text part of the file, a whole sentence or a whole table row. A quote never starts mid-sentence. If you leave words out, mark each cut with " … " and keep the words that carry the value and its subject. The quote must contain the value you log, and the value must say no more than the quote does (no added range, no unit the quote lacks, no second species). A table row is quoted as one line of the table with its column heads named in `where` (for example `"where": "Table 2, columns species | λmax (nm)"`).
- **Contextual corrections**: when an exact selected quote omits a qualification that changes its scientific interpretation, apply `oa-audit.md`, "Scientific context and counting". A source-verified qualification may supplement the selected quote only to qualify that same finding. Identify its supporting passage in `where` or `note`, retain the exact quote and the 40-word limit, and document each remaining numeric-linter flag. This exception does not permit an unrelated result, a new unsupported numerical claim, or invented context from inaccessible text; hold any unverifiable claim for review.
- **Check every quote** before committing: `python3 -I tools/views/quotecheck.py /tmp/oa/txt/<batch>-<entry>.txt records.jsonl`. Fix or drop each one that fails. PDF text can break a word at a line end (`photo- receptor`): quote what the file holds.
- **Grade** (BRIEF, "The evidence log" (`taxon` and `opened` bullets), `docs/views/audit/SAMPLE.md`, "The rule decided"): a value is graded by what the paper reports about the record's taxon. `m` for a value on the record's own taxon, its own or cited from another study (a cited value is also `partial`, below), whether that taxon is one species or the group the record names, when the statement is about that group as a whole. `g` for a taxon mismatch (a value for a wider or narrower group, one species or a few standing for a group, a relative) and for a value the paper predicts or presumes rather than measures (an opsin gene predicts a pigment; a "presumed dichromat"), with the prediction named in `method`. `i` only for a value you derive yourself (a conversion, a mean of values); the measured value goes in as its own record.
- **partial: true** whenever the value is not this paper's own measurement: a review, a compilation table, an introduction or discussion sentence citing another study ("… (Smith 1990)"), a value "after" or "from" someone else. Name the original study in `note` (authors, year) so it can be found. A review paper's values are all partial. A value read from a figure (not stated in text or table) is partial too, with "read from Fig. N" in `note`.
- **Source**: copy the object from `ci/oa/sources-r1.jsonl` exactly, with `access` "open"; `opened` is true. Never type a DOI, author or journal from memory.
- **One record a value**: two eyes, two sexes, two light conditions, two methods are two records, each with its own quote, `conditions` and `method`.
- Taxon names as the paper prints them, at the rank it gives; if the paper uses an old name, keep it and add the current one in `note` only when the paper itself gives it.

For each paper, also write one line in `docs/views/sources/<batch>.jsonl`: `{"doi": "...", "title": "<title exactly as the batch file gives it>", "url": "<the url from sources-r1>", "records": N, "read": "<batch> 2026-10-18", "note": "Full text read (control-room oa job run 1)<, accepted manuscript>"}`, with `"records": 0` when the paper holds no measurement of a BRIEF trait.

## Before every commit
- `python3 -I tools/senses/check.py docs/views/evidence/<batch>.jsonl` passes.
- Every new record's quote passed `quotecheck.py` against its text.
- `git status` shows no `.txt`, `.pdf`, `.xml`, `.bin` or `.pem` file staged. Paper text and the key never enter the repository.
Commit and push your branch at least every 15 minutes, between papers. Do not merge into `main` and do not open a pull request: the control room audits a seeded sample against the same texts and merges.
