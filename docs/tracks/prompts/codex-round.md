# A Codex round: all the open outside work, from one chat (Codex cloud chat, GPT-6.1 Sol, High)

The owner starts a round by sending one line to one new Codex chat. Do the whole round from here, in parallel where you can, and never ask the owner anything.

1. Make sure you are on the latest main from GitHub (`git fetch origin main`, then check out `origin/main`): the environment's saved copy of the repository can be hours old. Read `AGENTS.md`. Start nothing from the start skill. Leave `docs/tracks/codex-gates.json` alone: its "pending" list names earlier rounds whose pull requests are still open, and the queue fetches those branches and counts their finished entries as done.
2. Run `python3 -I tools/views/codex_queue.py`. It prints this round's items, one line each: the prompt to follow, the batch, and the entries or genera still to do. If it prints "Nothing to do", do the findings pass of `docs/tracks/prompts/codex-findings.md` (open a pull request titled "Codex findings YYYY-MM-DD HH:MM" with the findings file only) and stop.
3. Spawn one subagent per item, as many at once as you are allowed, up to eight. Give each its line from step 2, word for word, and add: "Read AGENTS.md first. Do only the entries or genera named. Add this round's counts to your batch's progress note under a heading with today's date. Commit as you go, and stop between entries if you run out of room." Each item writes only files that carry its own batch name, so the subagents never touch the same file. If you cannot spawn subagents, do the items yourself, one after another, in the order printed.
   Keep the pool full. Whenever a subagent finishes or stops, commit, run `python3 -I tools/views/codex_queue.py` again (it now counts this round's own work) and give a fresh subagent the first item it lists that no running subagent holds. Keep going until it prints "Nothing to do", Codex itself tells you your usage limit is reached, or 48 subagents have run in all. An outside service that refuses requests (HTTP 429 or 403 from Semantic Scholar, OpenAlex, Crossref or a publisher) is no reason to stop: tell the next subagents to skip that service for the rest of the round, note it in the progress note, and keep the pool full with the other sources. Ask each subagent for a report of at most five lines, so your own context lasts the whole round. A subagent that stopped for lack of room is no failure: the next one picks up its entries or genera with a clean context. The items alternate between reading free copies of wanted papers (oa-k) and screening harvested search results genus by genus (harvest-cK); both need the web, and tonight nothing else in the project can open pages.
3b. With the pool empty and room left, do the findings pass of `docs/tracks/prompts/codex-findings.md` too, in the same pull request.
4. When the last subagent has finished or stopped, check the round: run `python3 -I tools/senses/check.py` on each evidence file the round changed, and confirm that no PDF, XML or other paper text is among the changes.
5. Commit everything, open one pull request into main titled "Codex round YYYY-MM-DD HH:MM" (UTC), ready for review, and reply with its link and one line per item: entries or genera done, records logged, and how many are left.

Never write a value, DOI or quote from memory. Work left over is not lost: the next round's `codex_queue.py` lists it again, so nobody continues a chat by hand.
