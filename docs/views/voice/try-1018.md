# The views behind ?try=: their drafted rows (18 October)

One line for each of the 28 views reached only with `?try=`. Track `trydrafts`, branch `agent/trydrafts-1018`. The drafts are the `rows_draft` blocks in `views/<view>.json` (never shown); `docs/views/voice/REPORT.md` (block `rows-try`) gives the run, the reasons for every failure and the rows not sent. A draft passes when `tools/views/voice_check.py` finds nothing in it and every number in it is in a record it cites. The grades are the ones the evidence gives each row (m measured, g carried from a relative, i unknown). Rows about the drawing or the app's choices have no draft by design, so promoting a view's drafts also drops those rows.

A view is ready to offer on its drafts when they cover every row the view keeps and the review (`agent/recommend-1018`) held the view for its rows alone. Passing the checks says nothing about style, and the owner still reads each draft before it replaces a live row.
